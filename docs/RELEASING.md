# TextScope release command reference

Run from the TextScope repository root with the
[platform dependencies](DEVELOPER_GUIDE.md#dependencies-and-platform-setup)
installed. Use clean, committed sources for releases. Examples use `0.1.0`;
update filenames and tags when the version changes.

## Standalone packages

### Release build and tests

macOS/Linux:

```sh
cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DTEXTSCOPE_BUILD_TESTS=ON -DTEXTSCOPE_BUILD_EXAMPLE_PLUGIN=ON \
  -DTEXTSCOPE_BUNDLE_RUNTIME=ON -DTEXTSCOPE_INSTALL_EXAMPLE_PLUGIN=OFF
cmake --build build/release
ctest --test-dir build/release --output-on-failure
```

Add `-DCMAKE_PREFIX_PATH=/path/to/Qt` if needed. For Windows, use the
**MSYS2 UCRT64 shell** and add `-DCMAKE_CXX_COMPILER=g++`.
Ninja chooses concurrency automatically. Do not reuse another compiler's cache.

### Stage an installation (optional)

```sh
cmake --install build/release --prefix "$PWD/build/release/stage"
```

Creates the installed application layout and bundled runtime dependencies for
inspection. It does not install into the system application directory.

### Create a package

```sh
cpack --config build/release/CPackConfig.cmake -B build/release
```

CPack performs its own staging; the optional staging command is not required.

| Platform | Output | Launch after installation/extraction |
|---|---|---|
| macOS | DMG | Move `textscope.app` to Applications, then open it |
| Linux | TAR.GZ | `bin/tscope` |
| Windows UCRT64 | ZIP | `bin/tscope.exe` |

Packages and `.sha256` sidecars go to `build/release`. Extract complete archives,
not just executables. macOS builds are architecture-specific and ad-hoc signed,
**not Developer ID signed or notarized**.

For a macOS app installed in Applications, optionally expose the launcher
(check that the destination link does not already exist):

```sh
mkdir -p "$HOME/.local/bin"
ln -s /Applications/textscope.app/Contents/MacOS/tscope "$HOME/.local/bin/tscope"
```

Add that directory to PATH. Homebrew and pacman expose `tscope` automatically;
for standalone Linux/Windows archives, add the extracted `bin` directory to PATH.

## Source archive

```sh
cmake -P packaging/PrepareSource.cmake
```

Produces `build/releases/textscope-0.1.0-source.tar.gz` and its checksum.
The archive includes source provenance and excludes build/editor outputs.
Requires clean sources; use `-DALLOW_DIRTY=ON` only for unpublished local tests.
Different same-name archives are protected: use `-DOUTPUT=<new-absolute-directory>`
for another local snapshot.

## Package recipes

Run after source preparation:

```sh
cmake -P packaging/PrepareRecipes.cmake
```

Generates recipes under `build/releases/homebrew`, `build/releases/arch` and
`build/releases/msys2`, with the source version, URL and checksum.
Downloads default to
`https://github.com/deepak-rawat/textscope/releases/download/textscope-v<VERSION>`.
Override with `-DRELEASE_URL=<base-url>` or `-DARCHIVE=<absolute-source-archive>`.

Recipes build and test from source with package-manager dependencies and runtime
bundling **OFF**. Preparation alone does not compile, install or publish anything.

### Homebrew source-only formula and local tap

macOS only; run after source preparation:

```sh
cmake -DCOMMIT_TAP=ON -P packaging/PrepareLocalTap.cmake
brew tap local/releases "$HOME/local-releases/tap"  # Register once
brew update
brew install --build-from-source local/releases/textscope
brew test local/releases/textscope
open "$(brew --prefix textscope)/textscope.app"
tscope sample.log
```

The helper commits only the formula in a separate tap repository; Git author
configuration is required. Omit `-DCOMMIT_TAP=ON` to prepare without committing.
Default persistent layout:

```text
~/local-releases/tap/Formula/textscope.rb
~/local-releases/artifacts/textscope/    # Source archives and checksums
```

Override with `-DLOCAL_ROOT=<absolute-directory>`. Existing local edits and
conflicting archives are protected. Never publish a formula with a `file://`
URL; use the public formula generated by `PrepareRecipes.cmake`.
No Homebrew bottle or public tap is published automatically.

### Arch Linux

```sh
cd build/releases/arch
makepkg --syncdeps --cleanbuild
makepkg --printsrcinfo > .SRCINFO
sudo pacman -U ./textscope-*.pkg.tar.zst
```

### MSYS2 UCRT64

Use the UCRT64 shell:

```sh
cd build/releases/msys2
makepkg-mingw --syncdeps --cleanbuild
pacman -U ./mingw-w64-ucrt-x86_64-textscope-*.pkg.tar.zst
```

For unpublished Arch/MSYS2 testing, copy the matching source archive beside
PKGBUILD. Do not run makepkg as root. Windows managed packages and standalone
ZIPs both use UCRT64 GCC, not MSVC/vcpkg.

## Draft releases and manual publication

Update the version in `CMakeLists.txt`, commit and push, then run from the
repository root:

```sh
git tag textscope-v0.1.0
git push origin textscope-v0.1.0
```

Alternatively: **Actions > TextScope release > Run workflow**, supplying
an existing matching tag. The [release workflow](../.github/workflows/textscope-release.yml)
validates the tag/version and builds the exact tagged commit.
After all required jobs pass, it creates a **draft**, never publishes automatically.

Draft assets: macOS DMG, Linux TAR.GZ, UCRT64 Windows ZIP, Arch/MSYS2 packages,
source archive, and recipe archive; each has a `.sha256` sidecar, plus `SHA256SUMS`.
The Windows ZIP is built separately with bundling ON and smoke-tested after
extraction with MSYS2 removed from PATH. Its smoke test uses the native Windows
platform plug-in, which Qt may deploy under `share/qt6/plugins` rather than `bin`.

Download the draft assets and verify:

```sh
sha256sum --check SHA256SUMS
# macOS alternative:
shasum -a 256 --check SHA256SUMS
```

Before publishing:

- Test native installation/extraction, GUI launch, version, file/filter operations
  and uninstall. Test standalone packages without development dependencies.
- Check bundled dependencies, [license/source obligations](../THIRD_PARTY_NOTICES.md)
  and signing. Managed packages must not contain private runtimes or example plug-ins.
- Test recipes with local source archives until publication; draft URLs are not public.
- Open the draft in GitHub Releases and select **Publish release**.

Existing releases are not overwritten. If upload fails, inspect/delete the
partial draft before rerunning. Never move a release tag to different source.

### Outstanding release readiness

- Verify managed upgrades/uninstall, local-tap updates and additional architectures.
- Audit exact dependency versions, notices, source obligations and SBOM.

- Public Homebrew tap/bottle publication is not automated.

## Local validation

```sh
ctest --test-dir build --output-on-failure -R '^packaging$'
```

From the repository root:

```sh
actionlint .github/workflows/textscope-build.yml .github/workflows/textscope-release.yml
```

Packaging tests check source/recipe/asset safeguards, not native installer
certification. Failed CI test logs are available as workflow artifacts.
